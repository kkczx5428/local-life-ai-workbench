# 本地生活团购 AI 工作台产品设计

## Summary

面向本地生活代运营公司、团购服务商和探店机构，构建可自部署的开源工作台。产品围绕“商家资料 → 经营诊断 → 团购方案 → 内容协作 → 数据复盘”的完整服务交付链路展开，而不是做通用 AI 创作平台。

首版以人工审核和手动导出为边界，不依赖抖音官方接口，优先验证服务商的策划与交付效率。

## Product Modules

1. 服务商工作台：组织、成员、客户商家、项目、任务、仪表盘和权限。
2. 商家档案中心：门店、商品、客群、竞品、平台资料、目标和素材；支持表单与 Excel/CSV 导入、完整度检查和版本。
3. AI 商家诊断：输出商家画像、客群、商品方向、价格建议、卖点、风险、待办和依据。
4. 团购商品设计器：引流款、利润款、套餐、活动和复购券，包含价格、成本、毛利、规则、文案和适用场景。
5. 内容生产中心：选题、探店脚本、口播、分镜、标题、话题、拍摄清单和排期。
6. 素材资产库：图片、视频、音频、品牌资料、标签、搜索、版本和使用关系。
7. 审核协作：草稿、审核、修改意见、版本对比、责任人、截止时间和审计日志。
8. 数据复盘中心：销量、核销、退款、客单、毛利、内容表现和 AI 周报/月报。
9. AI 与适配器平台：可替换模型 Provider、垂直 Agent、模板、知识库和 Douyin/其他平台适配器。

## Phased Roadmap

- V0.1：身份组织、商家/门店、项目任务、文件、CSV/Excel 导入、基础权限和 Docker 部署。
- V0.2：AI Provider、商家诊断、完整度检查、编辑、版本、Markdown/PDF 导出、失败重试。
- V0.3：团购商品方案、套餐组合、毛利估算、规则文案、多方案比较和商家审核。
- V0.4：内容生产、脚本/分镜/口播、内容审核和发布排期。
- V0.5：素材库、协作评论、版本对比、任务看板和审计。
- V0.6：数据导入、经营指标、AI 复盘和商家汇报。
- V1.0：平台适配器、插件/Agent 注册、模板市场、API/Webhook、国际化和社区贡献体系。

## Architecture

采用模块化单体 Web，前后端边界清晰但首版不拆微服务。建议技术栈为 Next.js + TypeScript、PostgreSQL、Prisma/Drizzle、七牛云 Kodo 与阿里云 OSS、Redis/BullMQ（或数据库任务表）和 Docker Compose。开发环境支持本地文件存储，生产环境通过统一 StorageProvider 适配七牛云或阿里云。

核心模块边界为 Identity/Organization、Merchant、Store、Campaign、Product Plan、Content、Asset、Workflow、AI Runtime、Analytics 和 Audit。AI Runtime 统一处理 Provider、模型能力、幂等任务、状态、超时、重试、成本和错误；生产路径禁止静默伪成功。

公开 API 应围绕商家、方案、内容、任务和适配器定义稳定契约。StorageProvider 负责上传、下载、签名 URL、删除、元数据和对象迁移；凭证只在服务端保存，上传失败必须保留可重试状态。未来平台接入通过 PlatformAdapter 隔离，不让业务模块直接绑定抖音细节。

## Acceptance Scenarios

- 使用一个脱敏商家 CSV 完成导入、校验、补充资料和档案保存。
- 生成一份结构化商家诊断，人工修改后保存两个版本并导出 Markdown/PDF。
- 从诊断生成至少两套团购方案，展示价格、成本、毛利、规则和风险。
- 模拟 AI 超时、失败、重复请求和刷新恢复，任务状态可追踪且不会重复生成。
- 使用 Docker 全新启动，完成数据库初始化并通过 Demo 数据体验主链路。

## Open Source Defaults

优先采用传统开源许可证（Apache-2.0 或 AGPL-3.0），官方品牌、托管服务和增值模板可单独授权；最终许可证在仓库初始化前确认。仓库必须包含 README、Docker Compose、`.env.example`、安装向导、Demo 数据、迁移、API/架构文档、贡献指南、Issue 模板、Roadmap、Changelog、安全策略、隐私和免责声明。

## Assumptions

- 首版服务对象是代运营公司。
- 首版目标是内部提案与交付提效，不直接自动发布抖音。
- 支持本地模型及 OpenAI-compatible API。
- AI 结果默认需要人工审核。
- 统计数据首版允许手动或文件导入。
